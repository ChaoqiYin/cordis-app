# ADR 0008：共享模块按构建态提供，URL 是浏览器侧模块身份

## Status

已采纳（2026-11-11）。

## Context

`cordis-app dev` 的开发服务器过去把生产构建的共享模块直接发给浏览器。生产版
`react-dom` 不注册 renderer，React Refresh 没有可调度的树，每次刷新都是空操作。

失效是静默的：Vite 日志说模块已 self-accept，浏览器控制台没有报错，CLI 输出
干净。CSS 热更新正常，组件不更新，项目开发者容易把它当成自己的代码写错。现场
读数见 #81：`__REACT_DEVTOOLS_GLOBAL_HOOK__.renderers.size` 为 0，
`$RefreshReg$` 存在。

既有约束决定了修复方式：

- 共享模块必须只有一份实例。宿主、body 与插件指向同一个浏览器 URL，
  RuntimeContext 与 hooks 才只有一份。见术语表「共享模块」。
- 共享模块之间必须保持 external。多打一份 React 会让 hooks 崩溃。
- 共享模块清单是唯一真源，同时服务构建脚本、宿主 bundle 的 external 与浏览器
  的 import map 三处消费者。不能为构建态新增第二份清单。

问题因此不是「换掉某个文件」，而是「同一份模块身份如何对应两种构建产物」。

## Decision

### 1. 共享模块有开发与生产两种构建态

- 协议层提供 `development` 与 `production` 两种构建态。共享模块清单与浏览器
  URL 仍由协议层唯一提供。
- 共享模块构建脚本接受构建态参数。构建态只影响三件事：`NODE_ENV` 的构建期
  替换、压缩、sourcemap。
- 入口、产物文件名、共享模块之间的 external 关系在任何构建态下都不变。
- 两个构建态用独立进程构建，避免进程内模块缓存影响具名导出枚举。
- 生产构建产物继续放在原来的共享产物目录，包入口与类型声明入口不变；类型
  声明仍只跟随生产构建。
- 开发构建产物放在同级的新目录。该目录名属于 ui 包内部实现，不进入协议层
  与浏览器 URL；ui 包内测试通过内部常量引用，不硬编码字面量。
- 开发构建不压缩并生成 sourcemap，便于在浏览器里阅读与定位；生产构建保持
  现有压缩行为。

### 2. 消费端按运行形态选择，URL 不变

- 开发服务器固定读开发构建，包括 `/__shared/*.js` 的响应与共享模块的预热
  加载。
- 发布布局构建固定读生产构建，复制逻辑不变。
- 浏览器侧的 URL 集合、import map、插件 bundle 的 external、宿主 bundle 的
  external 都不变。不引入按环境判断的 external 或 import map 分支。
- 模块身份继续由 URL 定义。构建态只影响服务端读哪个文件，不影响浏览器看到
  的地址集合。因此插件产物不需要区分环境，宿主、body 与插件仍共用同一份
  实例。

### 3. 启动时校验开发构建

开发服务器启动时检查：

- 开发构建目录存在；
- 清单内每个共享模块的产物文件都存在；
- 产物带有与开发构建一致的 profile 标记。

任一检查失败时拒绝启动。错误信息包含缺失路径与构建命令。禁止静默回退到生产
构建：静默失效正是 #81 的根因，回退只会把同一个问题藏起来。

校验逻辑是 ui 包内的可复用函数。测试在临时目录上直接覆盖目录缺失、文件缺失
与标记不匹配三种失败，不读取或改动仓库里的真实产物。

### 三条不变量

1. 框架预构建产物必须标注构建态，由消费端运行形态选择，禁止跨构建态复用。
2. 开发构建缺失或不匹配必须显式失败，不静默回退到生产构建。
3. URL 是浏览器侧模块身份，构建态只影响服务端读哪个文件，不影响 URL 集合。

## Alternatives

**开发服务器直接读项目 `node_modules` 里的 React。** 绕过共享模块清单，会让
开发与生产的模块身份分叉；项目依赖版本还可能和宿主不一致，出现第二份 React
与 hooks 报错。

**只构建开发产物，开发与生产共用。** 开发产物带 sourcemap 且不压缩，发布布局
会因此变大；生产构建的压缩与 `NODE_ENV` 替换也一并丢失。

**缺少开发构建时回退到生产构建。** 服务不会中断，但组件热更新仍然失效，且没有
任何信号提示原因——正是本 ADR 要消灭的静默失效。

## Consequences

正面：

- 修改 body 或页面组件的 JSX、className 后，界面由 React Refresh 立即更新，
  与 CSS 热更新的行为一致。
- 开发构建的 `react-dom` 会注册 renderer，React Refresh 才有可调度的树；浏览器
  里 `renderers.size` 从 0 变为至少 1。
- 浏览器 URL、import map、插件 external 与共享模块清单都不变；运行时协议、
  插件生命周期、安装流程与打包模式不受影响。
- 开发构建缺失时立刻失败，并给出具体路径与构建命令，项目开发者不会再把它误判
  为自己的代码问题。

代价：

- 共享模块要构建两遍，构建时间增加；框架产物体积变大，因为多出一份未压缩、
  带 sourcemap 的开发构建。
- 开发前必须先有开发构建；框架不做自动构建，缺产物时只能显式失败。
- 产物多了一个 profile 标记，构建脚本与启动校验都要维护它；标记与构建态不一致
  时会在启动阶段报错。
- 开发构建目录名与构建态标记属于 ui 包内部实现：不进入协议层与浏览器 URL；
  ui 包内测试通过内部常量引用，不硬编码字面量。
