# 领域文档

工程类技能在探索本仓库代码前，应如何读取领域文档。

## 探索前先读

- 仓库根目录的 **`GLOSSARY.md`**
- **`docs/adr/`**：读与即将改动的区域相关的 ADR

如果这些文件不存在，**静默跳过**。不要提示它们缺失，也不要建议提前创建。`/domain-modeling` 技能（经由 `/grill-with-docs` 和 `/improve-codebase-architecture` 触达）会在术语或决策真正定下来时按需创建它们。

## 文件结构

单上下文仓库：

```
/
├── GLOSSARY.md
├── docs/adr/
│   ├── 0001-xxx.md
│   └── 0002-xxx.md
└── packages/
```

本项目是单上下文布局：整个仓库共享一份术语表和一套架构决策记录，`packages/` 下各子包不单独维护 `GLOSSARY.md` 或 `docs/adr/`。若将来某个子包形成独立的术语体系，再改为根目录 `GLOSSARY-MAP.md` 指向各上下文的多上下文布局。

## 使用术语表中的词汇

当你的输出涉及某个领域概念（issue 标题、重构提案、假设、测试名）时，使用 `GLOSSARY.md` 中定义的术语，不要漂移到术语表明确避开的同义词。

如果需要的概念还不在术语表里，这是个信号：要么你在发明项目并不使用的语言（请重新考虑），要么存在真实缺口（记下来交给 `/domain-modeling`）。

## 标记 ADR 冲突

如果你的输出与已有 ADR 相矛盾，请显式指出，而不是悄悄覆盖：

> _与 ADR-0007（事件溯源订单）相矛盾，但值得重新讨论，因为……_
